# KORDOC 파싱 에이전트 (세 번째 에이전트)

## 입력과 실행 범위
두 번째 `핵심논문-PDF-수집-에이전트`가 한 번의 수집 작업을 마치면, 그 작업에서 저장한 PDF 중 **단 한 편**을 선택해 KORDOC으로 전체 문서를 파싱하고 결과 검수를 **한 번만** 수행한다. 사용자가 파일을 지정하면 우선하고, 미지정이면 연구문제와 가장 직접적으로 관련된 문헌 중 텍스트층이 있는 파일을 선택해 이유를 기록한다. 폴더 전체 일괄 파싱, 반복 개선, 추가 논문 다운로드는 수행하지 않는다.

이 파일은 작업 지침이며 백그라운드 폴더 감시 프로그램이 아니다. 두 번째 에이전트의 수집 완료 절차에서 이 지침을 읽어 실행하거나 사용자가 직접 실행을 요청할 때 작동한다. 기본 입력 폴더는 `../AI 시대에 디자이너의 역할/핵심논문_PDF/`이며 연구를 바꾸면 해당 연구 폴더를 따른다.

## 파서와 실행 방법
- 공식 소스: https://github.com/chrisryugj/kordoc
- 프로젝트에 설치한 버전은 `package.json` 및 `package-lock.json`에 고정한다. 다른 파서의 출력을 KORDOC 결과라고 부르지 않는다.
- 이 폴더에서 `node parse-one.mjs "선택한 PDF 절대경로" "해당 연구 폴더/파싱결과/선택한 PDF 이름"`을 실행한다. 한 번의 KORDOC 호출로 Markdown과 구조화 JSON을 함께 저장한다.
- 현재 스크립트는 텍스트 PDF용으로 OCR·수식 OCR을 끄고 오프라인 모드로 실행한다. 스캔 PDF만 있거나 OCR이 필요한 경우 결과 한계를 보고하며 임의로 다른 엔진·외부 API로 대체하지 않는다.
- 출력: `parsed.md`, `parsed.json`, `run.json`, 추출된 이미지가 있으면 그 파일. 원본 PDF는 보존한다. `run.json`에는 입력 해시, 파서 버전·옵션, 실행 시각·상태를 기록한다.
- 성공한 동일 입력은 재사용한다. 실패나 기존 파일을 만났을 때 자동 재파싱하거나 덮어쓰지 않는다. 새 실행은 사용자가 재실행을 요청했을 때만 별도 출력 위치에서 수행한다.

## 검수 1회
보조 도구 pypdf·pypdfium2가 있는 Python으로 `review-once.py "파싱 출력 폴더"`를 한 번 실행하면 검수자료·원문 표본 이미지를 저장한다. 이어서 그 자료와 파싱 결과를 대조해 같은 검수의 보고서를 완성한다. 중단되면 기존 자료에서 이어가며 검수 스크립트를 다시 실행하지 않는다. 자동 표본에 실제 표가 없으면 같은 검수 안에서 실제 표 페이지를 추가 확인하고 기록한다. 완료 후 `review-run.json`에 완료 상태·최종 표본 페이지·보고서 경로를 추가한다.

한 번의 검수에서 다음 항목을 묶어서 확인한다.
1. 원본과 결과의 제목·저자, 페이지 수·페이지별 출력, 초록·본문·참고문헌의 존재.
2. 원문과 결과의 텍스트 비교를 통한 대량 누락·깨진 문자·중복 징후. 비교 지표를 완벽한 정확도 점수로 해석하지 않는다.
3. 원문의 첫 페이지, 표가 있는 페이지(없으면 중간 페이지), 마지막 페이지를 표본으로 삼아 다단 읽기 순서, 표·캡션·인용 등 구조를 확인한다. 검수용 텍스트 추출·렌더링은 보조 도구를 사용할 수 있으나 KORDOC의 산출물을 대체하지 않는다.
4. 파서 경고, OCR 미수행, 이미지·표의 미복원 부분과 표본 검수 범위를 기록한다.

`검수보고서.md`에 **사용 가능 / 보완 필요 / 사용 곤란** 중 판단, 확인한 페이지, 실제 발견사항, 후속 조치 제안을 작성한다. 원본 전체의 시각적 일치 검증을 하지 않았다면 완료했다고 말하지 않는다. 검수에서 문제를 찾아도 원문을 추측해 보충하거나 자동 수정·재파싱·재검수를 하지 않는다. `검수자료.json` 및 검수 시작 기록을 재사용하고, 검수보고서가 있으면 같은 결과를 다시 검수하지 않는다.

최종 보고에는 선택한 PDF 한 편, 파싱 결과 링크, 검수 1회 결과와 한계를 간단히 제시한다.
